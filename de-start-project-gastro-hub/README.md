# ☕ База данных сети кафе (Cafe Database)

Этот проект представляет собой комплексную разработку реляционной базы данных для сети заведений (кофеен, ресторанов, баров и пиццерий) на платформе **PostgreSQL**. 

Проект охватывает полный цикл работы с данными: от проектирования схемы и ETL-процесса до сложной аналитики и управления транзакциями.

## 🎯 О проекте

Работа разделена на несколько этапов, каждый из которых решает определенный класс задач:

### 1. Проектирование и создание схемы (DDL)
Создана схема `cafe` с нормализованной структурой таблиц:
* **Справочники:** `restaurants` (заведения с типом через кастомный `ENUM` и меню в формате `JSONB`), `managers` (менеджеры).
* **Связующие таблицы:** `restaurant_manager_work_dates` (история работы менеджеров в заведениях), `sales` (факты продаж).

### 2. Наполнение данными (DML / ETL)
Написаны скрипты для переноса данных из сырых таблиц (`raw_data`) в спроектированную схему. Использованы агрегации (`MIN`, `MAX`) для вычисления периодов работы менеджеров и `DISTINCT` для очистки от дубликатов.

### 3. Аналитика и управление данными (DQL / DDL / TCL)
Реализованы 7 сложных задач, оформленных в виде отдельных SQL-скриптов:
* **Задание 1:** Топ-3 заведения по среднему чеку в каждой категории (создано обычное представление `VIEW`).
* **Задание 2:** Динамика среднего чека по годам (расчет процентов изменения, создано `MATERIALIZED VIEW`).
* **Задание 3:** Топ-3 заведения по частоте смены менеджеров.
* **Задание 4:** Поиск пиццерии с самым большим ассортиментом пицц в меню (работа с `JSONB`).
* **Задание 5:** Поиск самой дорогой пиццы в каждой пиццерии (использование оконной функции `ROW_NUMBER`).
* **Задание 6:** Массовое обновление цен на капучино (+20%) с использованием транзакций и блокировки строк (`FOR UPDATE`) для предотвращения конфликтов.
* **Задание 7:** Миграция структуры таблицы менеджеров (добавление массива телефонов) с использованием эксклюзивной блокировки таблицы (`LOCK TABLE`) для безопасного изменения `ALTER TABLE` в условиях конкурентного доступа.

## 🛠 Технологии и инструменты
* **СУБД:** PostgreSQL
* **Работа с JSONB:** Операторы `->`, `?`, `jsonb_each_text`, `jsonb_set` для парсинга и изменения меню.
* **Аналитические функции:** `ROW_NUMBER() OVER (PARTITION BY ...)`, `DENSE_RANK()`.
* **CTE (Общие табличные выражения):** Конструкции `WITH` для декомпозиции сложных запросов.
* **Транзакции и блокировки:** `BEGIN`, `COMMIT`, `FOR UPDATE`, `LOCK TABLE IN SHARE ROW EXCLUSIVE MODE`.
* **Динамический DDL:** Изменение структуры таблиц на лету (`ALTER TABLE ... ADD/DROP COLUMN`).

## 📂 Структура проекта
* `ddl.sql` — создание схемы, пользовательских типов данных и таблиц.
* `insert.sql` — скрипты заполнения таблиц данными из исходных источников.
* `task_1.sql` ... `task_7.sql` — файлы с аналитическими запросами и операциями модификации данных.
* `README.md` — описание проекта.

## 🚀 Как запустить
1. Откройте ваш SQL-клиент (DBeaver, DataGrip, pgAdmin).
2. Выполните скрипт `ddl.sql` для создания структуры.
3. Выполните скрипт `insert.sql` (предварительно убедившись, что в базе есть сырые данные `raw_data`).
4. Открывайте и запускайте файлы `task_*.sql` по мере необходимости.
